# LiveKit Intelligent Interruption Handling - Implementation Guide

## Project Overview

This implementation solves the **LiveKit Intelligent Interruption Handling Challenge** by introducing a context-aware filtering layer that distinguishes between passive user acknowledgements (filler words) and active interruptions (commands).

---

## Problem Statement

**Challenge:** LiveKit's Voice Activity Detection (VAD) was too sensitive to user feedback, triggering false interruptions when users said filler words like "yeah", "ok", "hmm" while the agent was speaking.

**Required Solution:** Implement a context-aware logic layer that:
- Ignores passive filler words when agent is actively speaking/playing audio
- Interrupts when user provides actual commands or meaningful input
- Never modifies the VAD kernel (implement as pure logic layer)
- Maintains real-time latency requirements
- Handles semantic interruptions (e.g., "Yeah but wait")

---

## Solution Architecture

### Core Components

#### 1. **ContextAwareInterruptionFilter** (`interruption_filter.py`)
Main filtering engine with 4 interruption types:
- `IGNORE`: Passive acknowledgement - agent continues
- `INTERRUPT`: Active command - agent stops immediately
- `RESPOND`: Valid input when agent is silent
- `UNKNOWN`: Unclassified input

#### 2. **FilterDecision** (Data Class)
Captures all filtering decisions with:
- Decision type (IGNORE/INTERRUPT/RESPOND)
- Transcript analyzed
- Reasoning for the decision
- Agent state information
- Confidence score
- Timestamp for audit trails

#### 3. **Integration Point** (`agent_activity.py`)
Integrated into `_interrupt_by_audio_activity()` method - the existing interruption detection flow in LiveKit agents.

## Key Features Implemented

### 1. Configurable Ignore List
```python
DEFAULT_IGNORE_LIST = {
    "yeah", "yep", "yes", "ok", "okay", "alright", "right",
    "hmm", "uh", "uhh", "uhhhh", "um", "umm",
    "mm", "mmm", "mm-hmm", "mmhmm",
    "i see", "i understand", "got it", "sure", "cool",
    "no", "nope", "nah"
}
```

**Dynamically updatable:**
- `add_to_ignore_list(words)` - Add runtime customizations
- `remove_from_ignore_list(words)` - Remove words from filtering
- `update_ignore_list(words)` - Replace entire list

### 2. State-Based Filtering
Filter only applies when agent is actively engaged:
```python
filter_decision = filter_obj.evaluate(
    transcript="Yeah",
    is_agent_speaking=True,        # LLM generating text
    is_agent_playing_audio=True    # Audio playout active
)
```

- ✓ Agent Speaking → IGNORE filler words
- ✓ Agent Playing Audio → IGNORE filler words  
- ✓ Agent Silent → RESPOND to all input

### 3. Strong Interrupt Commands
Words that ALWAYS trigger interruption regardless of context:
```python
STRONG_INTERRUPT_WORDS = {
    "stop", "wait", "hold on", "hold up", "hold it", "pause",
    "no wait", "not wait", "but wait", "actually wait",
    "no stop", "stop stop", "shut up", "be quiet",
}
```

### 4. Semantic Interruption Detection
Detects mixed inputs containing conjunctions indicating intent:
```python
INTERRUPT_CONJUNCTIONS = {
    "but", "however", "actually", "wait", "hold",
    "i need", "i want", "i have", "let me",
}
```

**Example:** "Yeah but wait" → INTERRUPT (despite starting with "Yeah")

### 5. Text Normalization
Robust handling of spoken variations:
- Case-insensitive matching
- Punctuation stripped
- Extra whitespace normalized
- Filler variants recognized (uh, uhh, uhhhh, etc.)

### 6. Decision History & Audit Trail
Complete decision logging:
```python
history = filter_obj.get_decision_history()
# Returns: List[FilterDecision] with timestamps
```

### File: `livekit-agents/livekit/agents/voice/agent_activity.py`
Modified method: `_interrupt_by_audio_activity()` (lines ~1175-1240)

**Changes:**
```python
# Before: Direct VAD interrupt handling
# After: VAD → Filter Decision → Then interrupt

current_transcript = self._audio_recognition.current_transcript
filter_decision = self._interruption_filter.evaluate(
    transcript=current_transcript,
    is_agent_speaking=self._current_speech is not None and not self._current_speech.interrupted,
    is_agent_playing_audio=self._session.output.audio is not None and self._session.output.audio.is_playing,
)

if filter_decision.decision_type == InterruptionType.IGNORE:
    logger.info(f"[INTERRUPTION_FILTER] Ignoring: '{current_transcript}'")
    return  # Don't interrupt

# Otherwise proceed with normal interruption logic
```

## Troubleshooting

### Issue: Agent Still Stopping on "Yeah"
**Solution:** Ensure filter initialization in `__init__` method
```python
self._interruption_filter = ContextAwareInterruptionFilter(enable_logging=True)
```

### Issue: Real Interruptions Not Working
**Verify:** Check that strong interrupt words are in `STRONG_INTERRUPT_WORDS`
or that semantic content is detected properly via `_has_semantic_content()`

### Issue: Logging Not Appearing
**Check:** Confirm `enable_logging=True` is passed to constructor
